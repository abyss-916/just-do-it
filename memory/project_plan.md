## 大作业实施计划

### 定位
功能完整、架构清晰、工作量适中的多平台任务管理应用，用于软件工程课程大作业。不追求绝对完美，重点展示核心能力和工程素养。

---

### 一、现有核心功能清单（需验证完整性）

以下功能项目已有基础，需确认闭环、修补缺失：

| 功能 | 当前状态 | 需要做的 |
|------|----------|----------|
| 任务创建/编辑/删除 | 已有 Task CRUD 用例和 UI | 验证描述字段是否可用、编辑流程是否完整 |
| 任务完成/取消完成 | 已有 CompleteTask 用例 | 验证 UI 交互是否顺畅 |
| 分类管理 | 已有 Category CRUD | 确认创建分类后能关联任务 |
| 任务关联分类 | Task 表有 category_id 外键 | 确认任务详情页能切换分类 |
| 任务搜索 | 已有 SearchScreen | 验证搜索准确性 |
| 任务闹钟 | 已有 AlarmInteractor | 验证单平台实际触发效果 |
| 偏好设置 | 已有 PreferenceScreen | 确认主题切换可用 |
| 完成趋势图 | 已有 TrackerScreen + TaskGraph | 验证图表数据正确性 |

**动作：** 逐一跑通以上功能，记录并修复发现的问题。

---

### 二、建议新增功能（3 个亮点，工作量可控）

#### 功能 1：任务优先级

**描述：** 任务增加优先级标记（高/中/低），列表按优先级排序展示。

**工作量：中等（约 2-3 天）**

**涉及改动：**
- 数据库：`Task.sq` 增加 `task_priority` 字段（INTEGER，0=无, 1=低, 2=中, 3=高）
- 领域层：`Task` 模型增加 priority 字段，新增 `UpdateTaskPriority` 用例
- 数据层：Repository 映射、DAO 更新、本地数据源更新
- UI 层：任务创建/编辑页增加优先级选择器，列表页显示优先级标识（颜色圆点）
- 排序逻辑：列表默认按优先级降序 + 创建时间排序

#### 功能 2：逾期任务高亮 + 今日任务聚合

**描述：** 首页区分"今日任务"和"逾期任务"，逾期任务红色标记。

**工作量：小（约 1-2 天）**

**涉及改动：**
- 领域层：新增 `LoadOverdueTasks` 和 `LoadTodayTasks` 用例（基于 `task_due_date` 过滤）
- UI 层：任务列表页增加分区标题（今日 / 逾期 / 其他），逾期任务标题红色显示
- 不需要改动数据库

#### 功能 3：任务列表手势操作

**描述：** 任务列表项支持左滑完成、右滑删除。

**工作量：中等（约 2-3 天）**

**涉及改动：**
- UI 层：任务列表项外层包裹手势检测组件，滑动时显示背景提示（完成=绿色，删除=红色）
- 逻辑层：复用已有的 `CompleteTask` 和 `DeleteTask` 用例
- 不需要改动数据库和领域模型

---

### 三、不纳入本次范围的功能

明确不做，避免范围蔓延：

- 云端同步 / 多设备协作（需要后端，工作量过大）
- 子任务 / 检查清单（UI 复杂度高）
- 基于位置的提醒（平台差异大，容易出 bug）
- 看板 / 日历视图（纯 UI 工作量巨大）
- 语音输入（与核心业务无关）

---

### 四、实施顺序

```
阶段 1：现有功能验证与修复（2-3 天）
  1.1 跑通全部已有功能
  1.2 记录并修复发现的问题

阶段 2：任务优先级（2-3 天）
  2.1 数据库 schema 改动 + SQLDelight 生成
  2.2 领域模型 + 用例
  2.3 数据层映射
  2.4 UI 选择器 + 列表展示

阶段 3：逾期高亮 + 今日聚合（1-2 天）
  3.1 新增查询用例
  3.2 列表分区 UI

阶段 4：手势操作（2-3 天）
  4.1 手势组件封装
  4.2 集成完成/删除逻辑

阶段 5：收尾与测试（1-2 天）
  5.1 全流程回归测试
  5.2 代码质量检查（ktlint + detekt）
  5.3 补充必要的单元测试
```

**总工期估算：约 8-13 天（单人）**

### 五、答辩可展示的亮点

1. **KMP 跨平台** — 一套代码运行 Android、iOS、Desktop
2. **六边形架构** — 清晰的依赖方向，领域层独立
3. **模块化设计** — API/impl 分离，功能模块解耦
4. **完整的数据流** — SQLDelight → Repository → UseCase → ViewModel → Compose UI
5. **新增功能** — 优先级、逾期高亮、手势操作，体现对产品的理解
6. **质量保障** — ktlint + detekt + 单元测试

**Why:** 软件工程大作业需要展示完整的功能闭环和工程规范，而非追求功能数量。此计划聚焦现有功能打磨和 3 个有亮点的增量功能，工作量适中，答辩时有话可讲。

**How to apply:** 按阶段顺序推进，每个阶段完成后再进入下一个。不要跳过阶段 1 直接做新功能，确保基础功能稳定。
